# Snake 使用手册

Snake 通过内置授权（App 自身连接本机无线调试）以 shell 身份驱动设备端 98260 exploit，加载管理器 LKM。首次使用先完成一次无线调试配对，再一键越狱，无需安装 Shizuku / Stellar。

> Snake 目前支持 6.18.21、6.12.69、6.12.38、6.12.58、6.12.23、6.6.118 与 vivo 6.6.127 内核的设备，按完整 `uname -r` 精确匹配；未匹配的机型会提示不支持。

## 快速开始

1. 先安装所选 ROOT 管理器（KernelSU / FinaSU / KernelSU Next / BakaSU / SukiSU Ultra），**暂不支持ci版本的 KernelSU Next**。
2. 首页点右下角「一键授权」：授予本地网络/通知权限后，会自动打开开发者选项的「无线调试 → 使用配对码配对设备」，保持弹窗开启，在通知栏输入六位配对码（提交后通知会自动消失）。配对成功后标题旁的授权状态变成「已授权」，按钮变成「一键越狱」。**已经配对过的设备以后不需要再输配对码**：只要「无线调试」是开着的，打开 App 或从后台切回来都会自动重连；只有在设备不认得本机密钥（比如清除过 App 数据）时，才会再次要求输入配对码。**不需要安装或启动 Shizuku / Stellar**；配对码每次重启会变，重启后需重新配对，锁屏或关闭无线调试可能导致断连，回到首页会自动尝试重连。
3. 回到 Snake 首页点右下角「一键越狱」，等待输出区出现 `DONE`、`SU_ID_RC=0` 与 `uid=0(root)`。
4. 成功后管理器会自动拉起；开启对应开关时还会停用安全弹窗、加载 **SUSFS**（6.18/6.12 线，6.12 使用 `libsusfs_guard_lkm_612.so`；6.6.118、6.6.127 与 OriginOS 7 的 6.12.58 构建不支持）或 **VFS**（仅 6.18.21）。
5. 若输出区显示 **KernelSU module not loaded**，无需重启设备，直接再次尝试越狱即可。

## 权限与准备

- **内置授权优先**：App 自身通过无线调试 ADB 会话执行；Stellar / Shizuku 仍作为可选兜底保留，但不再是必需条件。
- **Android 17（API 37）需授予本地网络权限**：未授予时无法发现无线调试服务，配对流程会先申请该权限。
- **管理器必须先安装**：ksud 不随包内置，运行时从管理器 APK 的 `lib/arm64` 原地执行。
- **建议在干净开机后执行**；6.18.21、6.12.69、6.12.38、6.12.58、6.12.23、6.6.118、6.6.127 各是独立入口，App 按完整 `uname -r` 精确选择。

## 一键越狱流程

**preflight**（内核 release / trace 通道）→ **98260 UAF**（fake cred / SELinux 零写）→ **cred 子进程一次性 ksud late-load** → 等模块与 su → **收尾**（ksud install、卸内核防护、SUSFS、VFS、截图恢复、拉起管理器）。

每个内核版本有独立的 K 源文件和 `libk<版本>.so`；无源码级复用，共享引擎在 `plant_core.inc`。vivo 机型（6.12.23 / 6.12.58 vivo 构建）会在唤醒 root 子进程前清零 `vr.ko` 使用的 `__tracepoint_sys_exit->funcs` 槽位。

- **快路径** plant 约 2–3 秒、全流程约 4–9 秒；回收未命中时会多花几秒，属正常波动。
- **任一链失败后**：plant 持有的页会转交给 holder，同一 boot 可直接再点一次；不要手工 kill 或 reap holder。

## 功能说明

- **首页**：标题下那一行右侧有两个状态点——「已授权 / 未授权」表示内置授权是否连通，「已越狱 / 未越狱」表示内核里是否已加载 KernelSU 模块（重启后依然准确）。绿点为正常，红点为未就绪。下面三行分别是设备型号、内核版本与管理器（点「切换」可更换）；进度区显示当前环节与耗时；再往下是本次运行的实时输出；底部三个按钮是「扩展 / 命令 / 一键授权（授权后变一键越狱）」。
- **命令**：顶部输入条输入 shell 命令，点右侧蓝色箭头（或软键盘上的发送键）执行；未授权时以普通 shell 身份运行，右上角状态点是 `shell`，授权后变成绿色 `root`。右上「清空」可清掉当前记录。
- **常用命令**：输入框有内容时右侧出现书签，点它就能把当前命令存下来并起个昵称。底部「常用命令」点开列表，点一行直接执行；右侧 `⋯` 可以改名、改命令、置顶、删除，也可以打开「执行前确认」，这类命令在跑之前会再问一次。
- **扩展**：越狱后要执行的动作开关（安全弹窗、软重启、卸载内核防护、SUSFS、VFS、管理器热切换），以及 Droidspaces 模块下载。开关在下次越狱时生效。
- **关于**：右上角「!」进入，显示版本号、致谢名单与使用手册入口。
- **扩展 → 下载模块**（仅 6.18.21）：点「下载模块」获取 GitHub 上 `Droidspaces-LKM` 的最新 release 并保存到 `Download/Snake/`，之后到内核管理器「模块 → 安装」选择该文件刷入。模块不内置在 APK 中。
- **管理器选择**：首页「管理器」那一行点右侧「切换」弹出列表，选中后写入偏好，下次越狱按所选管理器加载。
- **Dynamic Switching**（6.18.21 / 6.12.69 / 6.12.38 / 6.12.58 / 6.12.23；6.6.118、6.6.127 不支持）：选中后首次干净 boot 运行一次，由 `libksud_universal.so` 加载通用 KSU LKM（初始 KernelSU，内嵌 6.18/6.12 双 KMI KO）。加载成功后扩展页出现「管理器热切换」，点一下按 KernelSU → KernelSU-Next → BakaSU → SukiSU → FinaSU 顺序轮换，无需重启或重新越狱；切换后会自动拉起目标管理器。

## 异常处理

| 日志 | 处理动作 |
| --- | --- |
| `PROBE_FAIL` / `kernel mismatch` | 当前内核不在支持列表（只按精确 `uname -r` 匹配已支持的 6.18.21 / 6.12.69 / 6.12.38 / 6.12.58 / 6.12.23 / 6.6.118 / 6.6.127）。 |
| `MANAGER` / `KSUD_MISSING` | 先安装对应的管理器 APK 再运行。 |
| `STALE_PLANT` | 上一轮 plant 仍在运行；等它转成 holder 后重试。 |
| `PLANT_FAIL` | plant 会保留 holder 并退出，同一 boot 可直接重试。 |
| `LATE_LOAD_FAIL` | 模块未在限定时间内出现；查看日志里的 ksud 输出，确认管理器版本匹配后直接重试。 |
| 内核崩溃/重启 | 属 98260 竞态固有风险，重启后再跑。 |

## 运行方式

- **6.18.21** → `libk61821.so`；**6.12.69** → `libk61269.so`（两个 OTA 构建按 uname 选调用点）。
- **6.12.38（PLR110）** → `libk61238.so`；**6.12.58（PLZ110 / V2505A OS6/OS7）** → `libk61258.so`；**6.12.23（V2505A）** → `libk61223.so`。
- **6.6.118（PKJ110 / PKH110 / Pad 等）** → `libk66118.so`（两个 OTA 构建按 uname 选调用点）；KMI android15-6.6。
- **6.6.127（vivo）** → `libk66127.so`；走 `hooks_defend` 门加载 LKM（`PYB110_GATE=1`），这条线的 6.12.58 OS7 构建同样走门加载。
- 以上全部按**精确 `uname -r`** 匹配；未匹配时点击「一键越狱」直接提示机型不受支持。
- 所有入口都直接以 App 原生库（`nativeLibraryDir`）原地运行，子进程 cwd/HOME/TMPDIR 都在 App filesDir，不向 `/data/local/tmp` 部署工具或写文件；ksud 也从已安装的管理器 APK 原地执行。SUSFS 对 6.18/6.12 线支持（6.12 使用 `libsusfs_guard_lkm_612.so`），6.6.118、6.6.127 与 OriginOS 7 的 6.12.58 构建不支持；VFS 开关仅对 6.18 入口开放。
- 仅用于自有设备的系统研究。
